**What to build:** Fixes from the 2026-09-26 triage for Build a Meal, saved meals, the Manual tab, Edit Meal and the barcode entry sheet. One agent, working through the list.
1. **Trashing a Saved meal offers Undo (112-005).** The trash icon on a Saved row (`log_meal_screen.dart:1061`, `:1184`) soft-deletes at once and shows nothing. After the delete, show a `MealvanaSnackbar` with Undo. Undo restores the row through a new `SavedMealsRepository.restore` (local first, re-dirtied for sync; `softDelete` is at `saved_meals_repository.dart:319`) and a controller method next to `deleteSavedMeal` (`meal_log_providers.dart:606`).
2. **Favourites from Build a Meal carry totals (112-007).** `DraftMealController.save` (`draft_meal_controller.dart:226`) hands `saveLogAsFavorite` a throwaway `MealLog` with no totals, so `saved_meals` gets null calories and macros and the Saved sheet previews 0 kcal. Pass the logged row itself, or at least the totals summed from the components. A macro that no item has stays null.
3. **"Save as favorite" in a logged meal's ⋯ on the Timeline (112-008, Lee).** The ⋯ offers only Edit food and Remove (`macro_dashboard/presentation/widgets/meal_card.dart:141`, wired at `macro_dashboard_screen.dart:1195`). Add Save as favorite, calling `MealLogController.saveLogAsFavorite` with the real log. Confirm with a `MealvanaSnackbar`. Put the label in the content system. `MealLogRow` and `TodayLogSection` are mounted nowhere: leave them alone or delete them, but do not revive them.
4. **Adding the same combo twice keeps the items visible (113-001).** `meal_component_editor.dart:148` keys rows `ObjectKey(item)`, and a Quick add combo adds the same `MealComponent` instances each time, so the second add throws "Duplicate keys found". Copy the components on add, or give each draft row its own id and key rows by that id.
5. **Back from a non-empty Build a Meal asks Discard / Keep building (113-007, Lee).** Today `build_meal_screen.dart` has no `PopScope`, and the auto-disposed `DraftMealController` drops the draft. Guard Back and the swipe the way `edit_meal_log_screen.dart:531` does, with two choices: Discard and Keep building. An empty draft leaves without asking. Labels go in the content system.
6. **Edit Meal saves decimal and empty calories (113-002).** `_buildUpdatedLog` (`edit_meal_log_screen.dart:359`) uses `int.tryParse`, so "250.5" and "" become null and `copyWith` keeps the old value while the screen says "Meal updated". Use `parseCaloriesInput` (as the Manual forms do): 250.5 saves 251, and an empty field clears calories to unknown. Clearing needs a way past `copyWith`'s null-keeps-old (unverified how `MealLog.copyWith` handles this).
7. **Edit Meal does not rewrite untouched macros (113-003).** The fields prefill with `toStringAsFixed(1)` (`edit_meal_log_screen.dart:126-129`) and save the shown text back, so 12.25 becomes 12.3. Write a macro only when its field changed; otherwise keep the stored value.
8. **Manual null macros show as unknown, not 0 (113-004).** `dashboard_assembler.dart:333` and `:551` map null calories to 0, and `MealItemData` (`dashboard_models.dart:119`) holds non-null doubles, so the Timeline reads "0 kcal · 0C · 0P · 0F". Make those fields nullable and show "—" for unknown in `meal_card.dart`. Build a Meal's total (`build_meal_screen.dart:413`, `:1150`) does the same for a no-data product. Day sums skip unknowns, as they already do for sodium (null ≠ 0).
9. **The empty-name error is visible (113-005).** On the Manual tab, Save with an empty name validates (`manual_log_form.dart:111`), but the "Name is required" message sits above the scrolled view. On a failed validate, scroll the name field into view and focus it.
10. **Barcode entry enforces 8 to 14 digits (113-006).** The sheet (`barcode_scanner_screen.dart:1028`) accepts any length, and the service answers "Invalid barcode format. Please try scanning again." (`barcode_scanner_service.dart:43`). Keep Look it up disabled, or show an inline message, until the entry has 8 to 14 digits. A typed number that fails the format check says so in words about typing, not scanning. Copy goes in the content system (`content_keys.dart`, `content_defaults.json`).
11. **`meal_saved_as_favorite` carries the log id (113-009).** Build a Meal's favourite sends `log_id: ''` because of item 2's throwaway log. Have `logFromComponents` return the new log's id and use it. Also set the log row's `saved_meal_id` to the favourite it made (unverified that the column is writable from the app).
