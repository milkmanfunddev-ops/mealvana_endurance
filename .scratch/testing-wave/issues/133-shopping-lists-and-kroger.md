**What to build:** The Shopping tab's offline copy, list labels, names and share text, Lee's "no list for a draft" ruling, and the Kroger screen's matching and cancel. One agent, as a list.
1. **An offline-copy tick survives until it is sent (110-001).** `ShoppingListController._replay` drops a tick when `tick.rowId ?? _rowNamed(current, name)` is null, and on the offline copy (`fromPlan`, no list id, items are not `ShoppingListItem`s) that is always null, so the retry timer deletes the tick 20 s after it is made. A tick with no row id waits while the state on screen is the offline copy (`listId == null`). It is matched by name only once the live list has loaded, and dropped only if that list really has no such line.
2. **Live-list ticks show on the offline copy (110-002).** `PendingShoppingTick.appliesTo` (`shopping_tick_store.dart:45`) matches on `listId` first, and the offline copy has `listId == null`, so `_withPending` never lays a live-list tick over it. On the offline copy, match a tick by `planId` when its list is that plan's list. Ticks made on the live list carry the plan id already.
3. **The offline copy has the last online tick (110-003).** The offline copy reads the Drift plan's `shopping` mirror, which is not updated when a tick settles online (the server's mirror is). After a tick on a plan's list settles, write the answered lines into the local plan's mirror through `MealPlanRepository` (a small new method, unverified name), so a cold offline start shows what this phone last saw.
4. **Offline Previous lists says it needs the network (110-004).** Offline, the sheet reads "No earlier lists yet." (`shopping_previous_empty`) over seven lists. When the state is offline and the tab never loaded the history, the sheet says the lists need a connection (new content key). It never says there are none.
5. **"An earlier list" only on an older list (110-005, 115-001).** `_summariesWith` re-sorts the history by `sortDate` after every tick and write. That drops the server's order, which puts the default list first (`shopping.ts` `orderedRows`), so a newer draft's list or a just-made list turns `isCurrent` false and the header reads "· An earlier list" while the menu has no Back to current list. Keep the server's default-first order when folding a write in. A list made with New list is pinned (`_openedListId` = its id) so it stays open, and it is never labelled earlier.
6. **Plurals (110-006).** "1 meals" and "1 items": `shopping_totals` and `shopping_item_count` (`shopping_list.dart:89,102`, Previous lists rows `shopping_tab.dart:993`) get one/many content keys, as `shopping_share_summary_one/_many` already do.
7. **Share on an empty list: check only (110-007).** Fixed by `d140a42d` (ticket 129, `_nothingToShare` in `shopping_share_button.dart`) after wave 30 ran. Add the widget test if none covers it.
8. **Jam goes to Pantry (110-008).** `classifyAisle` (`grocery.ts:49`) checks `AISLE_RULES` in order, and Produce's "strawberr" wins over Pantry's "jam". Add jam, jelly, preserves and marmalade to the Pantry `PRIORITY` list (`grocery.ts:48`).
9. **New list asks for a name (110-010, Lee).** New list opens a name dialog pre-filled "List · Sep 25" (today, in words). If that name is taken, " (2)" is added (then " (3)"), the same rule renames use (89-015, `uniqueShoppingListName`). The server's default name (`createList`, `shopping.ts`, now `List <ISO date>`) follows the same rule, so both agree.
10. **Share text names the list (110-011, Lee).** The title is the list's name in words (`shoppingListNameInWords`, "Week of Sep 20", "Race week extras"), not "Mealvana shopping list". The to-buy count already leaves out ticked rows (`toBuyCount`, 89-002); keep it.
11. **No shopping list for a draft (110-012, Lee; clarifies mp-244).** The server builds a plan's list at confirm and rebuilds it after edits to a confirmed (or once-confirmed) plan. A draft never gets one. `syncPlanList` (`shopping.ts:104`) skips a draft that was never confirmed, but still writes the `meal_plans.shopping` mirror. `confirmPlan` (`plan.ts:160`) calls `refreshShopping` while the plan is still a draft, so the list build at confirm must still run: pass a confirm flag, or build after `confirm_meal_plan`. Rebuild shopping list on a draft does nothing (or is not offered; unverified whether the Plan tab's ⋮ shows it on a draft). A new migration deletes existing draft lists (plan `status = 'draft'`, plan and list `confirmed_at` null), using the same predicate style as `20260925170100_drop_archived_draft_lists.sql`. Deleted plans' lists stay hidden: `deletedPlanIds` in `orderedRows`/`getList` already does this (88-019). Add a deno test that holds it.
12. **Kroger matching before Kroger login (111-002, Lee).** Matching needs a store, not a shopper: the server's `search` runs on the application token (`service.ts:290`), and `kroger/index.ts` checks only Pro. Drop `connected` from Match all (`kroger_screen.dart:280`) and from `KrogerState.canChooseProduct` (`kroger_controller.dart:132`). Add to Kroger cart (`kroger.export`, `kroger_screen.dart:372`, now hidden when not connected) shows for everyone and asks the shopper to connect when they are not.
13. **Cancelling Kroger sign-in is quiet (111-001).** Cancel on the system alert or X on the sheet throws a `PlatformException` (code `CANCELED`) from `flutter_web_auth_2`. `KrogerController._error` (`kroger_controller.dart:349`) maps it to `unexpected`, so the screen says "Something went wrong". Map it to `authorization_cancelled`. The screen stays disconnected with Connect Kroger back and shows no error snackbar. The server drops that attempt's `kroger_oauth_sessions` row: add a `cancel_connect` action in `service.ts` (the next `connect` already deletes old rows).
