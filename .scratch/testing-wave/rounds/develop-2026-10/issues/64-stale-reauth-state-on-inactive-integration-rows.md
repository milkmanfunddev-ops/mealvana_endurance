- **Every connect already clears both columns, on the row and on the server.** Each connect builds a fresh `IntegrationModel` with `lastSyncStatus: 'pending'` and no `lastSyncError` (the constructor default is null, `lib/features/integrations/domain/integration.dart:20-43`): V.O2 `vdot_oauth_service.dart:122-136` (`:131`), TrainingPeaks `training_peaks_oauth_service.dart:159-182` (`:176`), Final Surge `final_surge_oauth_service.dart:111-137` (`:121`), Garmin `garmin_oauth_service.dart:147-163` (`:158`). The download pass never overwrites a dirty local row (`syncFromRemote`, `:70-87`), so an unpushed reconnect is not undone by a stale server row. The controller drops its reauth flag on each connect: Final Surge `connect_training_controller.dart:682`, Garmin `:967`, V.O2 `:1199`, TrainingPeaks `:2022`.

So the ruling's "reconnect clears requires_reauth" holds in code today and only needs a test to keep it so. The one way an inactive row still gets sync state is a status write that lands after a disconnect:

1. **A status write never lands on a missing or inactive row.** `updateSyncStatus` (`integrations_repository.dart:414-443`) reads the row (`:420`) but writes whatever it is given, active or not. A TrainingPeaks or Final Surge sync, or a refused token refresh (`training_peaks_oauth_service.dart:316-328`), that finishes after the athlete tapped Disconnect writes `error`/`requires_reauth` and a code onto the row 47 just cleared, and pushes it (`:442`). Garmin's local mirror (`connect_training_controller.dart:1124-1150`) goes through the same method. After the read at `:420`, when `existing == null || !existing.isActive`, write nothing, skip `onSyncStatusWritten` (`:440`, so no Reconnect notice for a disconnected provider) and the push, and record it with the existing Report: `await _r.note('Sync status not written: integration inactive or missing', area: 'integrations', data: {'provider': provider, 'status': status, 'rowFound': existing != null})`. This is a skipped step on a sync path, so D9 asks for the note; `note` is the existing helper, not a new one.
