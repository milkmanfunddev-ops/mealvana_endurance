   ```sql
   -- Read first: rows per key class (the counts above), and the clashes the dedupe settles.
   begin;
   create temp table fp_map on commit drop as
   select fp.id, fp.user_id, fp.updated_at, fp.food_name,
          coalesce(u.name, fp.food_name) as key
   from public.food_preferences fp
   left join (
     select lower(display_name) as dn, min(name) as name
     from public.template_foods group by lower(display_name) having count(*) = 1
   ) u on u.dn = lower(fp.food_name) and fp.food_name !~ '^[a-z0-9_]+$';
   -- Two rows for one user and key: keep the newer; a tie keeps the row already keyed.
   delete from public.food_preferences where id in (
     select id from (
       select id, row_number() over (partition by user_id, key
         order by updated_at desc, (food_name = key) desc) as rn
       from fp_map) r where rn > 1);
   update public.food_preferences fp set food_name = m.key
   from fp_map m where m.id = fp.id and fp.food_name <> m.key;
   commit;
   ```

2. `load` after a refresh: `build` bumps the generation (it never resets to 0, so a pre-refresh load cannot match a post-refresh one) and clears the folded legacy names; a finishing load checks `ref.mounted` and its generation before writing state. Seam test case 5.
3. `save` twice at once: the repository serialises the two Drift writes in call order; the second save's immediate upload joins the first's in-flight upload and owes it one rerun, so the second save's rows go last and the flag clears only after them. Repository tests "two saves at once…" and "a save while an upload is in flight reruns it once".
4. `save`, then a plan generation before the upload lands: the flag is set before the Drift write, so `fetchAndCacheRemoteFoodPreferences` keeps the local rows and notes it. `syncFromRemote` already keeps local foods while the flag is set. Seam test case 2.
5. Settings closed mid-upload: the upload is owned by the repository (static per-user map), not the screen or controller; closing the screen loses nothing. A failed upload leaves the flag set, and the next dirty walk or Settings open retries.
