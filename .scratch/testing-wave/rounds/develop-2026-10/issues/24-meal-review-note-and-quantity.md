**What to build:** Two fixes on Review & Log. First, the AI's note shown on Review is saved with the meal. Second, an edited item keeps its quantity apart from its per-portion base, so a reopened item shows Quantity 2 over the original base and the portion text stays as the AI wrote it. Line numbers are from code at `d49956d3`.

1. **The note is saved (02-003, Lee).** `MealReviewScreen._logMeal()` (`meal_review_screen.dart:116-144`) calls `logFromComponents` without `notes`. Run 02 left row `40600e48…` with `notes` NULL. Everything below the screen already carries it: `MealLogController.logFromComponents` takes `notes` (`meal_log_providers.dart:400`, `:419`), `MealLoggingService` writes it (`meal_logging_service.dart:124`, `:147`), and `MealLog.toSupabaseJson` sends `'notes'` (`meal_log.dart:231`) through both upserts (`meal_log_repository.dart:162`, `:574`). Pass `notes: _result?.notes?.trim()`, with empty mapped to null. This is mealplanning's fix for the same Finding (23-002), commit `6f7415ef` ("testing-wave 83: the AI's note survives the save"). Cherry-pick its two lib hunks. The `edit_meal_log_screen.dart:115-129` hunk opens the notes panel whenever the log has a note, not only for logs without items, so Edit Meal shows the saved note. **If ticket 29's backport already carried `6f7415ef`, confirm it landed and skip this item.**
2. **`MealComponent` carries a quantity (02-005, Lee).** `meal_component.dart:10-97` has no quantity. The amount eaten lives only in the portion string, and the editor folds it in there (`meal_component_editor.dart:335-341`, `_persistedPortion`). Add `final double quantity` (default `1.0`) to the constructor and `copyWith`. `toJson` writes `'quantity'` only when it is not 1, so existing rows and payloads are unchanged. `fromJson` reads `(json['quantity'] as num?)?.toDouble() ?? 1.0`. The macro fields keep their meaning: what was **eaten** (portion × quantity). Every reader that sums `items` macros (`_sumComponents`, the Timeline, `meal_logs` totals) therefore stays correct with no change, and the server reads only totals. Add a getter `portionLabel` that returns `portion` at quantity 1 and `'${fmtQty(quantity)} × $portion'` otherwise (`fmtQty` from `portion_quantity.dart:32`).
3. **The Edit Item dialog opens over the base (02-005).** In `_EditComponentDialogState.initState` (`meal_component_editor.dart:265-291`), set `_baseQty = item.quantity` (not `1.0`, `:283`) and keep the base macros as `item.macro / item.quantity`. Show the eaten macros in the fields and `fmtQty(item.quantity)` in Quantity. `_recompute` (`:306-329`) already scales by `qty / _baseQty`. In `_save` (`:343-357`), drop `_persistedPortion` and save the Portion text as typed, with `quantity: qty` (a valid positive number, else the item's quantity) and the scaled field values. A manual Portion edit is still saved verbatim. Delete `_persistedPortion` and its doc lines (`:231-237`, `:326-341`). Leave `portion_quantity.dart`: `meal_items_editor.dart`, `food_display_utils.dart` and the nutrition-plan screens still use it.
4. **The row reads as two of the portion (02-005).** The row subtitle (`meal_component_editor.dart:134-145`) shows `item.portion`. Show `item.portionLabel` instead, so Banana at quantity 2 reads "2 × 1 medium banana (~118g) · 210 kcal …" and the AI's singular text and gram figure are never rewritten.
5. **Favourites tell 1 from 2 (follow-on of item 2).** `mealFavoriteMatchKey` (`meal_favorite_match.dart:32-38`) keys a component on `(name, portion)`. A meal of two bananas used to differ by its folded portion, and after item 2 it would match a one-banana favourite. Append `fmtQty(c.quantity)` to the component's key only when the quantity is not 1, so keys for existing favourites are unchanged.

**Findings:** 02-003, 02-005.

**Decisions:**
- Quantity is stored next to eaten macros, not next to per-portion macros. This keeps every existing reader and stored row correct, and a missing `quantity` reads as 1. Cost: for a fractional quantity, the base is recovered by division, and `calories` is an int, so 0.5 × 105 = 53 reopens over a base of 106. A drift of at most 1 kcal is accepted. Whole quantities round-trip exactly (2 → 210 → base 105).
- The portion label is "2 × <AI portion>". The AI's text and gram figure are never pluralised or rewritten.
- Not in this ticket: the swap path (`meal_review_screen.dart:82-114`, `edit_meal_log_screen.dart:487`) still writes scaled macros with the amount inside a built portion (`'2 servings'`) and quantity 1. That is a different code path that no Finding covers. The re-scan preview (`edit_meal_log_screen.dart:333`) only ever shows fresh quantity-1 items.
