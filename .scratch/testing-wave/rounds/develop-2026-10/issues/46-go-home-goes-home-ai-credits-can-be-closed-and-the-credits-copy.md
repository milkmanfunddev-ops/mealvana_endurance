1. **Go Home goes through the root redirect (32-002).** The router's `errorBuilder` (`lib/shared/core/app_router.dart:1092-1117`) has `onPressed: () => context.go('/welcome')` (`:1111`). `/welcome` is a public route (`:187-190`), so the redirect lets it through (`:204-207`) and a signed-in athlete stays on Welcome. Change it to `context.go('/')`. `/` is the one path the redirect resolves from app state (`:209-255`): `/main` for an onboarded, signed-in athlete; `/welcome` when the user is missing, not onboarded, logged out, or needs a resync; `/force-upgrade` and `/privacy-consent` when those apply. The app already goes home this way: `CustomAppBarBackButton`'s stackless fallback (`lib/shared/widgets/custom_app_bar_back_button.dart:59`) and the notification deep-link seed (`lib/shared/widgets/root_app_widget.dart:265`). Do not add a second session check in the button: the redirect is the one guard. The redirect's non-root branch (`:192-202`) checks only `supabase.auth.currentSession` and is not needed here. The signed-out case already reaches `/welcome` through the root branch.
2. **AI Credits gets the app's back control (32-003).** Both Scaffolds in `lib/features/ai_credits/presentation/screens/buy_credits_screen.dart` use a bare `AppBar` (`:48` coming-soon, `:144-154` enabled). A screen at the root of its stack has nothing to pop, so the bar shows no leading control. Add `leading: const CustomAppBarBackButton()` to both, which is what Coach Messages (`/athlete/feedback`) uses (`lib/features/coach_mode/presentation/screens/athlete_feedback_screen.dart:19`), the comparable route in the Finding. The button pops when `Navigator.canPop` (pushed from the balance chip, `credit_balance_chip.dart:26`, or from the out-of-credits dialog, `insufficient_credits_paywall.dart:62`) and otherwise goes to `/`, with a `LaunchTrail` line (`custom_app_bar_back_button.dart:45-60`). So one control covers both cases: Back when pushed, home when opened by deep link. Keep the `Restore` action.

**Decisions:**
- Go Home targets `/`, not `/main`. The startup redirect decides where home is, so a not-onboarded or force-upgrade user is never dropped onto the tabs. The `/main` route does not re-check onboarding.
- One back control, not a separate close button. `CustomAppBarBackButton` already handles the root-of-stack case and records it on the LaunchTrail tape (D9). At the root, the edge swipe still does nothing because there is nothing beneath to swipe back to. The visible button is the way out. Seeding `/main` under an OS deep link is a router-wide change that no Finding asks for.
- New keys, not "the existing key": there was none. The title moves with the body so the section comes from one place.
- Not in this ticket: the errorBuilder's own strings ("Page Not Found", "Go Home", `:1093-1112`) and the other hardcoded strings on AI Credits (`:58`, `:64-65`, `:94-116`, `:136`, `:166`, `:213`, `:305-306`) stay as Dart literals. No Finding covers them. Raise them in triage if wanted.
