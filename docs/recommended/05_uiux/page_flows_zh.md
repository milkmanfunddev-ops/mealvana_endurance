# Mealvana Endurance UI/UX 页面流程

## 概述
本文档定义了 Mealvana Endurance 的完整页面流程架构，这是一款为耐力运动员提供个性化营养规划的应用程序。流程围绕离线优先的移动体验设计，采用 Flutter Material Design 3 组件。

## 应用导航架构

### 导航模式
- **主导航**: 底部标签导航（3个标签）
- **次级导航**: 每个标签内的堆栈导航
- **深层导航**: 模态覆盖层和底部抽屉
- **路由器**: GoRouter 支持嵌套导航

### 标签结构
```
底部导航:
├── 🏃 计划 (标签1) - 主要流程
├── 📖 食谱 (标签2) - 次要内容  
└── ⚙️ 设置 (标签3) - 配置选项
```

## 核心用户流程

### 1. 首次用户流程（引导）

#### 1.1 应用启动 → 欢迎界面
**界面**: `OnboardingWelcomeScreen`
**目的**: 介绍应用价值主张
**组件**:
- 英雄图像（跑步者插图）
- 应用价值主张（3个关键优势）
- "开始使用" 主按钮
- "跳过" 文字按钮（直接进入主应用）

**用户操作**:
- 点击"开始使用" → 个人信息界面
- 点击"跳过" → 主应用（计划标签）

#### 1.2 个人信息收集
**界面**: `OnboardingPersonalInfoScreen`
**目的**: 收集必要的生物测量数据
**组件**:
- 进度指示器（第1步，共3步）
- 表单字段:
  - 性别选择（男/女/其他）
  - 生日选择器
  - 身高输入（cm/英尺-英寸 切换）
  - 体重输入（kg/磅 切换）
- "继续" 主按钮
- 返回按钮

**用户操作**:
- 填写必填字段 → 启用"继续"按钮
- 点击"继续" → 跑步习惯界面
- 点击"返回" → 欢迎界面

**验证规则**:
- 所有字段必填
- 年龄必须13岁以上
- 身高体重在合理范围内

#### 1.3 跑步习惯评估
**界面**: `OnboardingRunningHabitsScreen`
**目的**: 了解用户的跑步经验
**组件**:
- 进度指示器（第2步，共3步）
- 问题: "你跑步时会带水壶吗？"
- 切换开关（是/否）
- 视觉展示（带/不带水壶的跑步者）
- "继续" 主按钮
- 返回按钮

**用户操作**:
- 切换选择 → 更新UI视觉效果
- 点击"继续" → 食物偏好界面
- 点击"返回" → 个人信息界面

#### 1.4 食物偏好（清单界面）
**界面**: `OnboardingFoodPreferencesScreen`
**目的**: 收集详细的食物偏好
**组件**:
- 进度指示器（第3步，共3步）
- 完成百分比进度条
- 分类食物列表:
  - 跑前食物（8项）
  - 跑中食物（4项）
- 每种食物三状态选择:
  - ❤️ 喜欢（绿色）
  - 🤔 愿意尝试（橙色） 
  - ❌ 不喜欢（红色）
- "完成设置" 主按钮
- 返回按钮

**食物分类**:

**跑前食物**:
- 燕麦片
- 香蕉
- 希腊酸奶
- 咖啡
- 贝果
- 椰枣
- 希腊酸奶配浆果
- 蛋白质棒

**跑中食物**:
- 运动饮料
- 水
- 能量胶
- 能量糖

**用户操作**:
- 点击食物项 → 在偏好状态间循环
- 进度条随完成百分比更新
- 至少需要70%完成度才能"完成设置"
- 点击"完成设置" → 主应用（计划标签）
- 点击"返回" → 跑步习惯界面

**验证规则**:
- 必须为至少70%的食物设置偏好
- 不能将所有食物都设为"不喜欢"

### 2. 主应用流程（计划标签）

#### 2.1 距离/配速输入界面
**界面**: `DistancePaceGutEntryScreen`
**目的**: 营养计划生成的核心输入
**组件**:
- 界面标题: "规划你的跑步"
- 距离输入:
  - 数字选择器或文本字段
  - 单位切换（公里/英里）
  - 范围: 5-100公里 / 3-62英里
- 配速输入:
  - 时间选择器（MM:SS格式）
  - 单位显示（/公里 或 /英里）
  - 范围: 4:00-12:00 每单位
- 肠道训练水平:
  - 分段控制（新手/有经验）
  - 信息提示说明影响
- "生成计划" 主按钮（突出显示）
- 可选: "加载之前计划" 次要按钮

**用户操作**:
- 调整距离 → 验证范围，更新按钮状态
- 调整配速 → 验证范围，更新按钮状态  
- 选择肠道训练 → 更新计算参数
- 点击"生成计划" → 计划生成加载 → 当前计划界面
- 点击"加载之前计划" → 计划历史模态框

**验证规则**:
- 距离: 5-100公里（3-62英里）
- 配速: 4:00-12:00 每距离单位
- 肠道训练: 必选

**加载状态**:
- 用加载覆盖层替换界面
- 进度动画
- "正在计算您的个性化计划..."
- 持续时间: 1-3秒

#### 2.2 当前计划界面（结果）
**界面**: `CurrentPlanScreen`
**目的**: 显示生成的营养计划
**组件**:
- 计划头部:
  - 跑步详情（距离、配速、持续时间）
  - "生成新计划" 次要按钮
- 营养总结卡片:
  - 总卡路里及进度条
  - 碳水化合物、钠、液体及目标
- 可展开的计划部分:
  - **跑前** (前1-2小时)
  - **跑中** (每30分钟)
  - 每个部分显示:
    - 食物项目及分量
    - 营养分解
    - 时间指导
- 操作按钮:
  - "效果如何？"（反馈）
  - "调整宏量营养"（高级用户）
  - 分享图标（未来功能）

**用户操作**:
- 点击部分标题 → 展开/折叠详情
- 点击"生成新计划" → 距离/配速输入界面
- 点击"效果如何？" → 反馈流程
- 点击"调整宏量营养" → 调整宏量营养界面
- 在食物项目上滑动操作 → 替换食物界面

#### 2.3 调整宏量营养界面（高级）
**界面**: `AdjustMacrosScreen`
**目的**: 为高级用户微调宏量营养目标
**组件**:
- 当前目标显示
- 可调节滑块:
  - 碳水化合物率（克/小时）: 30-90克
  - 钠率（毫克/小时）: 200-700毫克  
  - 液体率（毫升/小时）: 400-800毫升
- 影响预览:
  - "这将影响您的计划..."
  - 更新食物推荐预览
- "更新计划" 主按钮
- "重置为默认值" 次要按钮

**用户操作**:
- 调整滑块 → 实时预览更新
- 点击"更新计划" → 重新生成计划 → 当前计划界面
- 点击"重置为默认值" → 恢复原始目标
- 返回按钮 → 当前计划界面（无更改）

#### 2.4 替换食物界面
**界面**: `SwapFoodScreen`
**目的**: 替换计划中的特定食物项目
**组件**:
- 标题: "替换 [食物名称]"
- 当前食物卡片（待替换）
- 替换选项:
  - 按类别和偏好过滤
  - 相似营养成分
  - 可用性指示器
- 营养对比表
- "替换" 主按钮
- "取消" 次要按钮

**用户操作**:
- 浏览替换选项
- 点击食物选项 → 选择替换品
- 比较营养价值
- 点击"替换" → 更新计划 → 当前计划界面
- 点击"取消" → 当前计划界面（无更改）

### 3. 反馈流程

#### 3.1 计划反馈界面
**界面**: `PlanFeedbackScreen`
**目的**: 收集对生成计划质量的反馈
**组件**:
- 问题: "这个营养计划如何？"
- 评级选项:
  - "与我认为应该使用的相当接近"（正面）
  - "比我认为应该使用的多得多"（太多）
  - "比我认为应该使用的少得多"（太少）
- 继续按钮（选择后启用）

**用户操作**:
- 选择评级选项 → 启用继续按钮
- 点击"继续" → 应用反馈界面

#### 3.2 应用反馈界面
**界面**: `AppFeedbackScreen`
**目的**: 收集整体应用体验反馈
**组件**:
- 问题: "您对应用的整体感受如何？"
- 响应选项（基于之前的答案）:
  - "我喜欢！提醒我使用它"（正面流程）
  - "有潜力，但我需要它..." → 文本输入
  - "不感兴趣" → 可选原因标签
- 提交按钮
- 跳过选项

**用户操作**:
- 选择响应 → 显示相应后续操作
- 填写可选文本输入
- 点击"提交" → 感谢消息 → 返回计划标签
- 点击"跳过" → 返回计划标签

### 4. 次要流程

#### 4.1 食谱标签流程
**界面**: `RecipesScreen`
**目的**: 浏览营养导向食谱（未来功能）
**当前状态**: 占位符界面
**组件**:
- "即将推出" 消息
- 未来食谱功能预览
- "返回计划" 按钮

#### 4.2 设置标签流程
**界面**: `SettingsScreen`
**目的**: 应用配置和用户管理
**组件**:
- 用户资料部分:
  - 基本信息显示
  - "编辑资料" 按钮
- 偏好部分:
  - "食物偏好" → 食物偏好界面
  - "单位" → 公制/英制切换
- 应用部分:
  - "关于" → 应用信息模态框
  - "隐私政策" → WebView
  - "服务条款" → WebView
- 账户部分（未来）:
  - 同步状态
  - 账户管理

**用户操作**:
- 点击"编辑资料" → 资料编辑界面
- 点击"食物偏好" → 食物偏好管理
- 切换单位 → 更新应用范围内单位
- 点击法律链接 → 在WebView中打开

#### 4.3 食物偏好管理
**界面**: `FoodPreferencesManagementScreen`
**目的**: 引导后修改食物偏好
**组件**:
- 与引导相同的食物列表
- 当前偏好突出显示
- "重置全部" 按钮
- "保存更改" 按钮
- 类别过滤器（跑前、跑中）

**用户操作**:
- 修改食物偏好
- 应用类别过滤器
- 点击"重置全部" → 确认对话框
- 点击"保存更改" → 更新偏好 → 设置界面

## 错误状态和边缘情况

### 网络错误状态
**离线模式**: 
- 应用完全离线运行
- 无需网络错误消息
- 所有核心功能可用

### 数据错误状态
**无效输入**:
- 实时验证与内联错误消息
- 在输入有效前禁用操作按钮
- 清晰的错误恢复指导

**未生成计划**:
- 食物不喜好过多 → 指导调整偏好
- 无效参数 → 建议修改输入
- 系统错误 → 重试选项及支持联系方式

### 空状态
**无之前计划**:
- 首次用户指导
- 突出显示的"生成您的第一个计划"号召性用语

**未设置偏好**:
- 指导完成食物偏好
- 快速链接到偏好界面

## 动画和过渡

### 界面过渡
- **标准导航**: 从右侧滑入（iOS）/ 淡入（Android）
- **模态展示**: 从底部滑上
- **标签切换**: 淡入过渡，内容持久化

### 微交互
- **按钮按下**: 轻微缩小（0.95倍）
- **加载状态**: 内容区域闪烁动画
- **成功操作**: 简短对勾动画
- **进度指示器**: 平滑动画进度条

### 内容动画
- **计划生成**: 加载旋转器及百分比
- **食物偏好选择**: 颜色过渡动画
- **宏量营养调整**: 实时数值更新
- **计划部分**: 平滑展开/折叠

## 无障碍考量

### 屏幕阅读器支持
- 所有交互元素的语义标签
- 状态变化的屏幕阅读器播报
- 导航的逻辑焦点顺序

### 视觉无障碍
- 高对比度颜色组合
- 最小44dp触摸目标
- 可缩放文本（支持动态类型）
- 颜色无关信息设计

### 运动无障碍
- 大而间隔良好的触摸目标
- 滑动操作的替代方案
- 语音控制兼容性

## 平台特定考量

### iOS 特定
- 导航栏样式符合iOS惯例
- 适当使用Cupertino控件
- iOS特定手势（滑动返回）
- 刘海设备的安全区域处理

### Android 特定
- Material Design 3 组件库
- Android返回按钮处理
- Material motion过渡
- 自适应图标和启动界面

## 性能考量

### 界面加载
- 在引导期间预加载下一界面
- 缓存生成的计划以立即显示
- 食物偏好列表的懒加载

### 内存管理
- 界面卸载时释放控制器
- 食物图标的图像缓存
- 大数据集的高效列表渲染

### 电池优化
- 最小背景处理
- 高效本地数据库查询
- 优化动画性能
