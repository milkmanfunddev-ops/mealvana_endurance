# Mealvana Endurance 技术设计

## 概述
本文档概述了Mealvana Endurance营养规划应用各架构层的详细技术设计，专注于每个架构层的具体实现模式、数据结构和技术方法。

## 表现层技术设计

### 控制器实现模式
**技术**: 带@riverpod代码生成的AsyncNotifier

**控制器结构设计**:
```dart
@riverpod
class ScreenController extends _$ScreenController {
  ServiceClass get _service => ref.read(serviceProvider);
  ContentService get _contentService => ref.read(contentServiceProvider);

  @override
  FutureOr<StateType> build() {
    // 使用缓存内容进行同步初始化
    return initialState;
  }
}
```

**状态管理设计**:
- **状态类**: 带copyWith方法的不可变类
- **AsyncValue处理**: 加载、数据和错误状态
- **错误恢复**: 通过AsyncValue.guard内置重试机制

### Widget设计模式
- **ConsumerWidget**: 用于响应式状态监听
- **监听模式**: 通过ref.listen进行错误处理
- **加载状态**: 一致的加载器和骨架状态
- **错误显示**: 集中化错误消息处理

## 应用层技术设计

### 服务类设计
**业务逻辑协调**:
- 通过依赖注入进行跨功能通信
- 数据操作的仓库协调
- 复杂业务规则实现
- 外部API集成处理

**服务实现模式**:
```dart
@riverpod
ServiceClass serviceClass(ServiceClassRef ref) {
  final repository = ref.watch(repositoryProvider);
  return ServiceClass(repository);
}
```

### 内容管理服务设计
**动态内容处理**:
- **内容键**: 所有UI文本的类型安全字符串常量
- **回退策略**: 远程 → 缓存 → 打包默认值
- **实时更新**: 无需应用重启的后台内容刷新
- **本地化支持**: 多语言内容管理

## 领域层技术设计

### 数据模型设计
**实体结构**:
- **不可变类**: 所有领域模型使用不可变设计
- **类型安全**: 所有业务实体的强类型
- **验证规则**: 内置业务规则验证
- **序列化**: 用于存储的JSON序列化支持

**核心模型**:
- **UserProfile**: 带验证约束的生物测量数据
- **FoodPreference**: 三级偏好系统（喜欢/不喜欢/愿意尝试）
- **NutritionPlan**: 带版本控制的复杂嵌套结构
- **FeedbackData**: 带元数据的用户满意度评级

### 业务规则设计
- **营养算法**: 基于ACSM的计算公式
- **偏好逻辑**: 食物过滤和推荐逻辑
- **验证规则**: 输入验证和约束检查
- **安全限制**: 算法安全边界和警告

## 数据层技术设计

### Drift数据库实现
**表设计结构**:
```dart

  Users,
  FoodPreferences, 
  NutritionPlans,
  AppContent,
  Feedback,

  @override
  int get schemaVersion => 1;
```

**关键技术特性**:
- **外键约束**: 引用完整性执行
- **自动时间戳**: 创建/更新时间戳管理
- **索引优化**: 查询性能的策略性索引
- **迁移系统**: 带测试的逐步模式演化

### 仓库实现设计
**类型安全数据访问**:
- **生成类**: 编译时验证查询
- **事务支持**: 数据操作的ACID合规性
- **批处理操作**: 高效批量数据处理
- **流支持**: 通过watchSingleOrNull进行响应式数据更新

**查询优化技术**:
- **预准备语句**: 频繁操作的可重用查询
- **联接查询**: 带类型安全的复杂关系查询
- **分页支持**: 高效大数据集处理
- **连接池**: SQLite WAL模式提高性能

### 同步设计
**离线优先同步策略**:
- **本地优先**: 所有写入首先进入本地存储
- **后台同步**: 周期性上传/下载操作
- **冲突解决**: 带用户通知的最后写入获胜
- **重试逻辑**: 失败操作的指数退避

**技术同步细节**:
- **变更跟踪**: 基于时间戳的脏标志系统
- **批量上传**: 高效网络使用模式
- **数据完整性**: 同步操作的校验和验证
- **回滚支持**: 同步失败时的事务回滚
