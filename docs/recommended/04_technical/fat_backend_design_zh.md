# 胖后端架构设计

## 概述

Mealvana Endurance实现"胖后端"架构，其中业务逻辑、内容和算法参数存储在服务器端并在本地缓存。这使得非技术团队成员能够通过后端界面进行更改而无需代码部署，同时通过本地缓存和回退机制维持离线功能。

## 架构设计

### 内容管理策略
设计将内容与代码分离，允许动态更新而无需应用发布。

**内容流设计：**
```
后端内容存储 → 本地缓存 → UI组件
                    ↓
              打包默认值（回退）
```

**设计组件：**
- **远程内容存储**: 数据库中的集中内容管理
- **本地缓存**: 高性能本地内容存储
- **回退系统**: 打包默认值确保离线功能
- **内容服务**: 所有内容的统一访问层

### 内容结构设计

**两类组织：**

#### UI文本内容
按屏幕和功能分层组织的所有面向用户的字符串：
- 基于屏幕的组织（main_screen、plan_screen等）
- 验证消息和错误文本
- 帮助文本和说明内容

#### 算法参数
营养计算的科学常数和阈值：
- 能量计算常数
- 碳水化合物吸收参数
- 水合计算因子
- 安全限制和阈值

## 设计优势

### 对非技术团队成员
- **内容独立性**: 无需技术知识即可更新任何文本
- **算法调整**: 基于用户反馈调整营养参数
- **立即影响**: 更改在应用中反映而无需代码部署
- **无审核流程**: 内容更新绕过应用商店审批

### 对开发团队
- **清晰分离**: 代码中无硬编码字符串或魔法数字
- **测试灵活性**: 不同场景的简易内容模拟
- **配置敏捷性**: 无需代码更改即可添加新内容类别
- **变更跟踪**: 内容修改记录和版本化

### 对业务运营
- **快速响应**: 基于用户反馈的快速调整
- **A/B测试**: 用用户群体测试不同算法参数
- **部署效率**: 减少应用商店发布需求
- **市场适应**: 为不同用户群体定制内容

## 内容管理设计

### 访问模式设计
**分层键系统**: 嵌套内容结构的点符号访问
- 按功能和特性的逻辑组织
- 通过预定义键常数的类型安全访问
- 缺失内容的回退值系统

### 缓存策略设计
**多层缓存**: 通过分层缓存的性能优化
- 会话持续访问的内存缓存
- 离线访问的本地存储缓存
- 首次启动场景的默认内容包

### 版本控制设计
**内容版本控制**: 跟踪和管理内容随时间的变化
- 更新检测的版本比较
- 回滚能力的变更历史
- 较老应用版本的兼容性检查

## 安全设计考虑

### 内容验证设计
- **输入验证**: 使用前验证所有获取的内容
- **类型安全**: 参数类型检查确保系统稳定性
- **范围验证**: 算法参数限制在安全范围内
- **回退保护**: 无效内容从不导致应用崩溃

### 访问控制设计
- **运行时只读**: 应用执行期间内容不可变
- **开发控制**: 内容更改需要开发工作流程
- **版本管理**: 受控的内容部署过程

## 性能设计

### 加载策略设计
**启动优化**: 最小化应用启动时间影响
- 启动时的单一内容加载操作
- 整个会话的内存缓存
- 内容访问无网络依赖
- 初始加载后的即时可用性

### 资源管理设计
**高效资源使用**: 优化内存和存储消耗
- 紧凑的内容表示
- 大内容部分的懒加载
- 内存高效的缓存策略
- 最小网络开销

## 集成设计

### 后端集成策略
**服务分离**: 内容和应用逻辑之间的清晰边界
- 内容服务独立于业务逻辑
- 统一的内容访问接口
- 后端技术抽象

### 离线设计策略
**弹性操作**: 确保无论连接如何都能正常运行
- 本地优先的内容访问
- 后端不可用时的优雅降级
- 向打包默认值的透明回退
