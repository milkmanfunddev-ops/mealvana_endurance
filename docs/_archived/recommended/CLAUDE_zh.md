# Mealvana Endurance 文档标准规范

## 文档分类定义

### 架构设计文档
**目的：** 描述系统的整体结构、组件关系和设计决策

**应包含：**
- 系统整体架构图和组件关系
- 技术选型和架构决策的理由
- 数据流向和系统边界
- 模块划分和职责分工
- 关键架构模式和原则

**严禁包含：**
- 具体代码实现
- 详细的API定义
- 具体的数据库字段设计
- 外部工具的使用教程
- 编码规范和命名约定
- 具体的开发工作流程

### 技术设计文档
**目的：** 描述技术方案的设计思路和关键技术决策

**应包含：**
- 技术方案选择和对比
- 系统设计的技术考量
- 关键技术组件的设计思路
- 技术风险和解决方案
- 性能和安全考虑
- 技术约束和限制

**严禁包含：**
- 具体代码实现（包括类定义、方法签名等）
- 详细的配置文件内容
- 具体的安装和部署步骤
- 外部工具的使用手册
- 详细的开发教程

## Design vs Implementation 严格区别

### Design（设计）
- **概念层面：** 说明"做什么"和"为什么这样做"
- **抽象描述：** 使用文字、图表、流程图来描述
- **决策导向：** 重点在设计决策和理由
- **技术无关：** 尽可能避免特定技术的细节

### Implementation（实现）
- **执行层面：** 说明"具体怎么做"
- **代码层面：** 包含具体的代码、配置、命令
- **操作导向：** 重点在具体操作步骤
- **技术相关：** 涉及特定技术的详细使用

## 文档引用规范

### 路径引用要求
- **必须使用相对路径**，如：`../requirements/project_requirements.md`
- **禁止使用绝对路径**，如：`/Users/xxx/project/docs/...`
- **目的：** 确保文档在不同机器和环境下的可移植性

### 源文档标注
每个整理后的文档必须在末尾包含：
```
## 来源参考
基于：相对路径到原始文档
```

## 文档质量标准

1. **内容准确性：** 严格按照原始文档内容，不添加、不删减、不改写
2. **分类准确性：** 按照文档的实际内容本质进行分类，不按照原始目录结构
3. **翻译准确性：** 中文翻译准确反映英文原意，保持技术术语一致性
4. **引用完整性：** 所有引用和链接使用相对路径，确保跨环境可用

## 文档同步要求

**关键规则：** 在`/docs/`目录下优化任何文档时，必须同步优化对应的中文文档。

### 同步标准：
1. **内容一致性：** 中英文版本必须包含相同信息
2. **结构一致性：** 保持相同的章节标题和组织结构
3. **更新时机：** 英文版本修改后必须立即更新中文翻译
4. **质量标准：** 中文版本必须符合与英文版本相同的质量标准

### 实施流程：
- 更新任何`.md`文件后，立即更新对应的`_zh.md`文件
- 确保翻译准确性，同时保持技术术语一致性
- 验证两个版本都遵循相同的文档分类标准
- 更新两种语言版本的来源参考

## 禁止事项

1. **禁止在设计文档中包含代码**
2. **禁止创造新内容**，只能整理和翻译现有内容
3. **禁止输出implementation文档**，只输出design文档
4. **禁止将外部工具教程当作架构或技术设计**
5. **禁止将编码规范混入架构设计**
6. **禁止更新英文文档而不同步中文版本**

此规范确保中英文两个版本文档的专业性、准确性和可维护性。
