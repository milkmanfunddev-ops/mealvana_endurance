# 系统架构设计文档

## 1. 架构概述
*[来源: CLAUDE.md, PROJECT_ANALYSIS_FINDINGS.md]*

耐力运动营养规划系统采用模块化的分层架构设计，将计算逻辑、优化算法、数据管理和用户接口清晰分离。系统基于Python构建，采用函数式编程与面向对象相结合的设计范式。

### 1.1 设计原则
- **模块化**：功能组件独立，便于维护和扩展
- **可扩展性**：支持新运动类型和食物的添加
- **优雅降级**：关键组件失败时有备用方案
- **类型安全**：使用强类型确保数据一致性
- **科学驱动**：所有计算基于循证研究

## 3. 核心模块设计
*[来源: CLAUDE.md, PROJECT_ANALYSIS_FINDINGS.md]*

### 3.1 用户接口层

#### integrated_fueling_planner.py
**职责：**
- 命令行参数解析
- 输入验证和转换
- 调用业务逻辑层
- 格式化输出结果

**关键组件：**
- ArgumentParser：CLI参数处理
- 数据验证器：确保输入合法性
- 输出格式化器：生成用户友好的结果

### 3.2 业务逻辑层

#### 3.2.1 运动计算引擎

##### endurance_fueling.py（多运动支持）
**职责：**
- 运动特定的能量消耗计算
- 营养需求计算
- 多运动类型支持

**核心数据结构：**
- FuelInput：输入参数封装
- FuelOutput：计算结果封装
- SportSpecificData：运动特定数据

**关键算法：**
- ACSM跑步方程
- 功率基础自行车计算
- MET值能量消耗
- 铁人三项分段计算

##### run_fueling.py（遗留系统）
**职责：**
- 仅支持跑步的计算
- 保持向后兼容性

#### 3.2.2 优化引擎

##### nutrition_optimizer.py
**职责：**
- 食物组合优化
- 约束条件管理
- 偏好集成
- 便携性评分

**核心功能：**
- 多目标优化
- 按小时营养目标
- 食物类别约束
- 份量控制

##### optimizer_lp.py
**职责：**
- 线性规划求解
- 混合整数规划（MILP）
- 约束编程

**关键特性：**
- PuLP库集成
- 优雅降级到枚举
- 高效大规模求解

### 3.3 数据层

#### 3.3.1 食物数据库
*[来源: nutrition_optimizer.py文档, PREFERENCES_GUIDE.md]*

**数据结构：**
```
FoodItem:
  - name: 食物名称
  - nutrition: 营养信息
    - carbs_per_serving: 碳水化合物
    - protein_per_serving: 蛋白质
    - fat_per_serving: 脂肪
    - fiber_per_serving: 纤维
    - sodium_per_serving: 钠
    - water_per_serving: 水分
  - portability: 便携性评级
  - race_provided: 赛道提供
  - serving_constraints: 份量约束
```

**食物分类：**
- 赛前食物（10种）
- 比赛中食物（4种）

#### 3.3.2 运动员偏好
*[来源: PREFERENCES_GUIDE.md, athlete_preferences.json]*

**偏好格式：**
```json
{
  "food_name": "preference_level"
}
```

**偏好级别：**
- like：优先推荐
- try：可以接受
- dislike：完全避免

## 4. 数据流设计
*[来源: 整体代码分析]*

### 4.1 计算流程

```
用户输入
   ↓
输入验证和解析
   ↓
运动特定计算
   ├─→ 能量消耗计算
   ├─→ 营养需求计算
   └─→ 时间段划分
   ↓
优化算法执行
   ├─→ 约束条件设置
   ├─→ 目标函数定义
   ├─→ LP求解/枚举
   └─→ 结果评分
   ↓
输出格式化
   ↓
用户可读结果
```

### 4.2 优化流程
*[来源: PRODUCT_ROADMAP.md, optimizer_lp.py文档]*

```
营养目标设定
   ↓
食物候选集筛选
   ├─→ 偏好过滤
   ├─→ 阶段适用性
   └─→ 约束检查
   ↓
优化求解
   ├─→ LP求解器（如可用）
   │    ├─→ 变量定义
   │    ├─→ 约束编码
   │    └─→ 目标优化
   └─→ 枚举方法（备用）
        ├─→ 组合生成
        ├─→ 约束验证
        └─→ 评分排序
   ↓
结果后处理
   ├─→ 整份调整
   ├─→ 便携性优化
   └─→ 最终评分
```

## 8. 错误处理和降级
*[来源: PROJECT_ANALYSIS_FINDINGS.md, optimizer_lp.py]*

### 8.1 优雅降级策略
```
LP求解器不可用 → 枚举方法
优化超时 → 返回当前最优解
约束无解 → 放松非关键约束
```

### 8.2 错误处理层级
- 输入验证错误：明确提示用户
- 计算错误：记录日志并尝试恢复
- 系统错误：安全退出并保存状态
