Where each test lands in the deploy pipeline

The uncovered edges (the actionable part)

1 · The real Garmin wire — never exercised. The deployed garmin-push/garmin-ping have never received a live completion; G6 (“sync beats skip”) is proven at the matcher seam only. Cheapest closure: POST a synthetic Garmin webhook payload at the deployed garmin-push on dev against a seeded skipped workout, and assert the row upgrades — a real test of the deployed function, no watch required. Candidate for the probe.mjs live-gate script.
2 · Prod has zero test stages. Everything right of landing is operator care + idempotent SQL. Minimum viable: run the three verify queries + one read probe against prod after its schema step, and a single smoke session on the released build (T14-style) before comms go out.
3 · T11’s CI credential status is unverified. The self-hosted workflow runs Patrol on every push, but whether that runner has secrets/integration_test.env — and therefore whether the remote half executes or silently self-skips in CI — is unknown. One question for Lee.
