## Final Issue Resolved: DateTimeColumn Parsing

### The Problem (November 4, 2025)
After fixing table name mismatches, the app encountered:
```
FormatException: Invalid radix-10 number (at character 1)
2025-09-24 19:35:46.868228 +00:00
^
```

**Root Cause**: Seed database stored `created_at` as TEXT (ISO timestamps), but Drift's `DateTimeColumn` expects INTEGER (Unix milliseconds).

### The Fix
Updated seed database schema for three tables:
- `foods` (31 items)
- `product_types` (17 items)
- `carb_loading_foods` (27 items)

**Conversion Formula**:
```sql
CAST((julianday(created_at) - 2440587.5) * 86400000 AS INTEGER)
```

**Result**: Database reduced from 72KB to 68KB after VACUUM.
