# spec/domain/ — domain-rule SSOTs

**Created by ruling (Xuan, 2026-08-31; intake `2026-08-26-brick-eligibility-logic-ssot.md`).**

The third truth family. `spec/<engine>/` holds calculation truth (formula · band · citations);
`spec/design/` holds rendering truth (the contracts screenshots can't hold). This family holds
**domain rules**: what a thing *is* and when an action is *offered* — truths with no formula and
no hue, owned by no single surface. A domain rule is stated once here and cited by every surface
and engine that touches it, so a surface migration can never silently drop the behaviour again
(the brick flow was lost twice for exactly that reason).

Same lifecycle as the other families: PROPOSED → RATIFIED by Xuan, dated RULED stamps for
post-ratification additions, `DEVIATIONS.md` for observed-but-unratified code behaviour,
vectors via `spec-to-vectors` (here: `vectors/domain/<rule>.json`, input = a day's ordered
facts → expected verdicts), conformance against the app's published predicates.
