# Feature-Oriented Architecture (FOA) Implementation Guide

## Overview

Mealvana Endurance strictly follows **Andrea Bizzotto's Feature-Oriented Architecture (FOA)** patterns. This document outlines the mandatory implementation patterns that ALL developers must follow.

## 🚨 CRITICAL: FOA Compliance Requirements

### 1. Controller Pattern (MANDATORY)

**❌ NEVER USE:**
```dart
class Controller extends StateNotifier<AsyncValue<State>> {
  Controller(this._service) : super(const AsyncData(null));
  final Service _service;
}

final controllerProvider = StateNotifierProvider<Controller, AsyncValue<State>>((ref) {
  final service = ref.watch(serviceProvider);
  return Controller(service);
});
```

**✅ ALWAYS USE:**
```dart
import 'dart:async';
import 'package:riverpod_annotation/riverpod_annotation.dart';
import '../../../content/application/content_service.dart';
import '../../../content/domain/content_keys.dart';

part 'screen_controller.g.dart';

@riverpod
class ScreenController extends _$ScreenController {
  ServiceClass get _service => ref.read(serviceProvider);
  ContentService get _contentService => ref.read(contentServiceProvider);

  @override
  FutureOr<ScreenState> build() {
    // Load content synchronously from in-memory cache
    final title = _contentService.getValue(ContentKeys.screenTitle, 
        defaultValue: 'Default Title');
    
    return ScreenState(
      title: title,
      isLoading: false,
    );
  }

  Future<void> performAction() async {
    state = const AsyncLoading();
    
    state = await AsyncValue.guard(() async {
      final result = await _service.performBusinessLogic();
      return state.valueOrNull?.copyWith(result: result) ?? 
             ScreenState(result: result);
    });
  }
  
  Future<void> refresh() async {
    await _contentService.refreshFromBackend();
    ref.invalidateSelf();
  }
  
  String getErrorMessage(String? error) {
    return _contentService.getValue(ContentKeys.errorGeneric, 
        defaultValue: error ?? 'Something went wrong. Please try again.');
  }
}
```

### 2. State Class Pattern

```dart
class ScreenState {
  final String title;
  final bool isLoading;
  final String? errorMessage;
  final DataType? data;

  const ScreenState({
    required this.title,
    this.isLoading = false,
    this.errorMessage,
    this.data,
  });

  ScreenState copyWith({
    String? title,
    bool? isLoading,
    String? errorMessage,
    DataType? data,
  }) {
    return ScreenState(
      title: title ?? this.title,
      isLoading: isLoading ?? this.isLoading,
      errorMessage: errorMessage ?? this.errorMessage,
      data: data ?? this.data,
    );
  }
}
```

### 3. Screen Widget Pattern

```dart
class Screen extends ConsumerWidget {
  const Screen({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final controllerState = ref.watch(screenControllerProvider);
    
    // Listen for errors and show snackbars
    ref.listen<AsyncValue<ScreenState>>(
      screenControllerProvider,
      (_, state) {
        if (!state.isLoading && state.hasError) {
          ScaffoldMessenger.of(context).showSnackBar(
            SnackBar(content: Text(state.error.toString())),
          );
        }
      },
    );
    
    return controllerState.when(
      data: (state) => _buildScreen(context, state, ref),
      loading: () => const Scaffold(
        body: Center(child: CircularProgressIndicator()),
      ),
      error: (error, stack) => Scaffold(
        body: Center(
          child: Text('Error loading content: $error'),
        ),
      ),
    );
  }
  
  Widget _buildScreen(BuildContext context, ScreenState state, WidgetRef ref) {
    return Scaffold(
      appBar: AppBar(title: Text(state.title)),
      body: Column(
        children: [
          // Use state values, not hardcoded strings
          Text(state.title),
          ElevatedButton(
            onPressed: state.isLoading 
                ? null 
                : () => ref.read(screenControllerProvider.notifier).performAction(),
            child: state.isLoading 
                ? CircularProgressIndicator() 
                : Text('Action Button'),
          ),
        ],
      ),
    );
  }
}
```

## 4. Layer Architecture

### Presentation Layer (`/presentation/`)
- **Widgets**: UI components that display state
- **Controllers**: `AsyncNotifier` classes managing screen state
- **Providers**: Generated by `@riverpod` annotation (never manual)

### Application Layer (`/application/`)
- **Services**: Business logic classes
- **Use Cases**: Complex business operations
- **Providers**: `@riverpod` for dependency injection

### Domain Layer (`/domain/`)
- **Models**: Data classes with `copyWith`, `==`, `hashCode`
- **Entities**: Core business objects
- **Enums**: Type-safe constants

### Data Layer (`/data/`)
- **Repositories**: Data access implementations
- **Data Sources**: API clients, database access
- **DTOs**: Data transfer objects

## 5. ContentService Integration (MANDATORY)

### All Controllers Must:

1. **Access ContentService**: 
```dart
ContentService get _contentService => ref.read(contentServiceProvider);
```

2. **Use ContentKeys for ALL text**:
```dart
final title = _contentService.getValue(ContentKeys.screenTitle, 
    defaultValue: 'Fallback Title');
```

3. **Never hardcode strings**:
```dart
// ❌ WRONG
return ScreenState(title: 'Settings Screen');

// ✅ CORRECT
return ScreenState(
  title: _contentService.getValue(ContentKeys.settingsTitle, 
      defaultValue: 'Settings Screen')
);
```

4. **Provide error messages through ContentService**:
```dart
String getErrorMessage(String? error) {
  return _contentService.getValue(ContentKeys.errorGeneric, 
      defaultValue: error ?? 'Something went wrong. Please try again.');
}
```

## 7. Error Handling Pattern

### Use AsyncValue.guard():
```dart
Future<void> performAction() async {
  state = const AsyncLoading();
  
  state = await AsyncValue.guard(() async {
    // This automatically catches exceptions and creates AsyncError
    final result = await _service.riskyOperation();
    return currentState.copyWith(result: result);
  });
}
```

### Handle Errors in UI:
```dart
ref.listen<AsyncValue<State>>(
  controllerProvider,
  (_, state) {
    if (!state.isLoading && state.hasError) {
      final controller = ref.read(controllerProvider.notifier);
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(content: Text(controller.getErrorMessage(state.error.toString()))),
      );
    }
  },
);
```

## 9. UI/Controller Separation Rules (CRITICAL)

### 🚨 ABSOLUTE PROHIBITIONS:

**❌ FORBIDDEN IN UI SCREENS:**
- Business logic methods (especially underscore methods like `_generateMacros()`)
- API calls to Supabase edge functions  
- Complex data transformations and calculations
- Direct repository access
- Analytics tracking (except UI-specific events)
- Data parsing and validation logic

**❌ FORBIDDEN IN CONTROLLERS:**
- Navigation logic (`context.push()`, `context.pop()`)
- UI state management (`setState()`, focus management)
- Scaffold operations (showing snackbars, dialogs)
- Widget building logic

### ✅ REQUIRED RESPONSIBILITIES:

**UI Screens ONLY:**
- Widget building and rendering
- Form validation (UI-level only)
- Navigation calls
- Loading state display
- Error message display via ScaffoldMessenger
- Input collection and passing to controllers

**Controllers ONLY:**
- All business logic operations
- API calls and data fetching
- Data transformation and calculations  
- Error handling and logging
- Analytics tracking
- Repository operations
- State mutations

### Example: FOA-Compliant Pattern

**❌ VIOLATION Example:**
```dart
class ScreenWidget extends ConsumerStatefulWidget {
  Future<void> _generateData() async {
    // ❌ This is business logic in UI!
    final supabase = Supabase.instance.client;
    final response = await supabase.functions.invoke('generate-data');
    // ... processing logic
  }
}
```

**✅ CORRECT Example:**
```dart
// UI Screen - ONLY UI concerns
class ScreenWidget extends ConsumerStatefulWidget {
  Future<void> _handleButtonPress() async {
    // ✅ UI-only: keyboard, loading state
    FocusScope.of(context).unfocus();
    setState(() => _isLoading = true);
    
    try {
      // ✅ Delegate ALL business logic to controller
      await ref.read(screenControllerProvider.notifier).generateData(
        inputValue: _controller.text,
      );
      
      // ✅ UI-only: navigation
      if (mounted) {
        context.push('/next-screen');
      }
    } catch (error) {
      // ✅ UI-only: show error from controller state
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(content: Text(error.toString())),
      );
    } finally {
      // ✅ UI-only: hide loading state  
      setState(() => _isLoading = false);
    }
  }
}

// Controller - ONLY business logic
@riverpod
class ScreenController extends _$ScreenController {
  Future<void> generateData(String inputValue) async {
    // ✅ Parse and validate input
    final parsedValue = double.tryParse(inputValue) ?? 0.0;
    
    // ✅ Call external services
    final supabase = Supabase.instance.client;
    final response = await supabase.functions.invoke('generate-data', 
      body: {'input': parsedValue});
    
    // ✅ Process and store results
    final repository = await ref.read(repositoryProvider.future);
    await repository.saveResult(response.data);
  }
}
```

## 10. Common Violations to Avoid

### ❌ DON'T:
- Use `StateNotifier` instead of `AsyncNotifier`
- Create manual providers instead of using `@riverpod`
- Hardcode strings in controllers or widgets
- Access services through constructors
- Use `try/catch` instead of `AsyncValue.guard`
- Forget to integrate ContentService
- Skip the `part` directive for code generation

### ✅ DO:
- Use `@riverpod` AsyncNotifier pattern for all controllers
- Access all services through `ref.read()`
- Load all text content through ContentService
- Use `AsyncValue.guard()` for error handling
- Include ContentService integration in every controller
- Run code generation after changes
- Follow the four-layer architecture strictly
