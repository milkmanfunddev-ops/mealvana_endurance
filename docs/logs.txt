  1. Upload Failure StateError (MEALVANA-ENDURANCE-7R)

  - Impact: 360 events, 2 users, ESCALATING (last 21 hours)
  - Error: StateError: Upload failed for activities: Uploaded 0/5 activities; 5 failed
  - Root Cause: Orphaned brick_id foreign key. Parent brick was deleted remotely but child activities still reference it. When dirty children try to upload, Supabase FK constraint fails (23503). SyncCoordinator.ensureSynced() then
   throws a StateError instead of handling gracefully.
  - User Impact: None visible (caught in try/catch), but generates 360+ Sentry alerts
  - Fix:
    a. In activities_repository.dart uploadDirtyRecords: add remote existence check for parent bricks, or catch 23503 errors and clear orphaned brick_id
    b. In sync_coordinator.dart:201: don't throw StateError for partial upload failures — respect the "best effort" design pattern

  2. Brick FK Constraint Violation (MEALVANA-ENDURANCE-3W)

  - Impact: 163 events, 20 users, ongoing since Nov 2025
  - Error: PostgrestException: FK constraint fk_activities_brick_id violated (23503)
  - Root Cause: softDeleteFromProvider() and _queueImmediateActivityUpsertById() bypass the batch upload safeguards. When a provider-synced activity that belongs to a brick gets soft-deleted, the immediate upload path doesn't
  check if the parent brick exists in Supabase first.
  - Fix: In _queueImmediateActivityUpsertById, check if the activity has a brick_id and whether the parent exists remotely. If not, clear brick_id before uploading (same pattern uploadDirtyRecords already uses for orphaned
  activities).

  3. UnmountedRefException in Events Controller (MEALVANA-ENDURANCE-7H)

  - Impact: 6 events, 4 users
  - Error: Cannot use the Ref of eventsControllerProvider after it has been disposed
  - Root Cause: events_controller.dart:_backgroundSync() calls ref.read() after await without checking ref.mounted. When user navigates away mid-sync, the provider gets disposed but the async work continues.
  - Fix: Cache all ref-dependent values (repo, syncCoordinator, logger) before the first await, add if (!ref.mounted) return; check before ref.invalidateSelf(), and use cached logger in catch block.

  4. No Current User During Google Sign-In (MEALVANA-ENDURANCE-75 + 76)

  - Impact: 10 events combined, 3 users
  - Error: Exception: No current user found to update auth provider
  - Root Cause: Race condition during post-onboarding Google account linking. Supabase session changes instantly from anonymous to Google, but the local DB still has the old auth_user_id. When updateAuthProvider() calls
  getCurrentUser(), it queries with the new auth ID which doesn't match the local record.
  - Fix: In auth_migration_service.dart, replace the updateAuthProvider() call with _handleFreshLogin() which was already designed to avoid this race condition, or pass the user ID explicitly to avoid getCurrentUser().

  5. GoRouter "Nothing to Pop" (MEALVANA-ENDURANCE-6B)

  - Impact: 13 events, 2 users
  - Error: GoError: There is nothing to pop
  - Root Cause: CustomAppBarBackButton calls Navigator.of(context).pop() without checking canPop() first. Triggered from sport_preferences_hub_screen.dart:40.
  - Fix: In custom_app_bar_back_button.dart, add Navigator.of(context).canPop() guard before popping. If there's nothing to pop, fall back to context.go('/settings').
