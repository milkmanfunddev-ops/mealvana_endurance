  v5 pipeline — R1 unrounded chain, Q-003 strength flat 27 g/hr, Q-014 30 %E

  Legacy engine suites migrated to the rulings.
- **Parity**: `DailyBaselineCalculator` (Dart mirror, onboarding preview)
  updated in lockstep; shared fixture regenerated by
  `calculate-daily-macros/tools/generate-parity-fixtures.ts` — never
  hand-edit it.
- **Schema**: Drift v18 — `activities.planned_time` / `actual_time` /
  `calories_burned` + `'deleted'` tombstone status; Supabase migrations
  `20260814120000` (two-time + tombstone) and `20260814121000`
  (`plan_recalc_log`).
- **F27 `recalculateAfterSync`** + one calibration row per run
  (`recalculate.ts`; retro mode in `index.ts` IS the F27 path).
- **Tombstones everywhere**: deleteActivity soft-deletes both sides; download
  paths include tombstones; change-detection + garmin-push/ping match
  tombstones FIRST (ruled key: platform id, else platform+sport+start ±15 min);
  disconnect purges deliberately stay hard-delete.
- **UI**: flag-gated `lib/features/macro_dashboard/` (fail-closed
  `MACRO_DASHBOARD_ENABLED`; Fuel Timeline remains default) — workout card
  **v2** (G1–G7: unified-skip model Q-D6 — left-swipe reveals a neutral
  Skip/Unskip, never dragonfruit; SKIPPED has a passive trigger (past day,
  unresolved — derived, never on the current day) and an active one (Skip
  press, allowed today, writes `status='skipped'` + clears `actual_time`);
  G3 suppresses BOTH swipe directions on a verified card; no delete
  affordance on the card — deferred bundle), energy card (3 faces × 2
  expansions, P-1/P-2/Q-D3), timeline rail (S-7: a skipped card has no
  timestamp, tucks after every timed card, neutral rail ink), Breakdown Pager
  (3 pages, live data), card tap → `openActivityFuel`. S-2: a skipped
  workout's kcal/fuel leave every surface figure (assembler `counts`).
  10 goldens (v2 manifest; `workout_card_skipped` regenerated citing Q-D5 +
  Q-D6/D-2) + 22 gesture/behaviour tests covering all 17 v2 manifest rows +
  intraday-display vector suite (24) in `test/features/macro_dashboard/`
  and `test/features/daily_macros/`.
- **Skip write path**: `ActivitiesRepository.skipWorkout/unskipWorkout` →
  service → `ActivitiesController.skipWorkout/unskipWorkout` (optimistic,
  same no-loading-flash pattern as mark-done); undo restores the exact prior
  row via `restoreActivity`. Macro inputs: every activity-derived query in
  `DailyMacroService` filters `status != 'skipped'` (zero session demand,
  platform-resolution SKIPPED addition); `macro_cache_invalidation.dart`
  invalidates the window on a skip toggle only (mark-done still does NOT).
- **Sync beats skip (G6)**: `_shared/garmin/activity_completion.ts` —
  `findMatchingSkippedActivity` (ruled key: platform id, else same sport ±15
  min) runs before the day-wide planned match; every atomic completion
  update uses `GARMIN_COMPLETABLE_STATUSES` (planned/draft/skipped) so a
  Garmin completion lands on a skipped row and clears the skip. Client-side
  `_mergeProviderUpdate` (TP/FS/Runna re-sync) now PRESERVES
  `planned_time`/`actual_time`/`calories_burned` (v1 gap: any provider title
  tweak silently reverted a mark-done).
- **Deliberate spec-over-prototype call**: the reference rendering's skipped
  card still shows the orange fuel link; workout-card.md v2 says "no
  `orange` anywhere on the card" and S-2 says fuel windows leave — the app
  hides the link on a SKIPPED card. If product prefers the prototype, it is
  a one-line change in `workout_card.dart` + a golden regen citing the
  ruling.
- **TP-imported `'skipped'` rows** (`activity_mapper.dart` maps TP `skipped`
  → `ActivityStatus.skipped`) now render as actively-skipped cards (Unskip
  available) and stop counting toward macros — the handoff's default
  (athlete is the tiebreaker). Raise via QA `intake/` if product disagrees.

**Deploy-coupled constants — do not flip early:**
`_expectedAlgorithmVersion` in `daily_macro_targets_repository.dart` is held
at `'v5.0.0'` until the v6 engine deploys (flipping early causes a cache
invalidation storm — the 2026-08-14 dashboard flicker); Supabase
`app_config.current_schema_version` → 18 only when the build carrying Drift
v18 ships (triggers client delete-and-resync).

   indefinitely. The flow chains a debugPrint tap in front of the app
   handler so the device log names the real failure — copy that pattern
   into new flows.
