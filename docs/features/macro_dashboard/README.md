# Macro Dashboard (bundle daily-macros-dashboard@v1)

Status ledger + remaining plan for the daily-macro dashboard redesign.
Branch: `feature/daily-macro-dashboard-redesign` (based on
`feature/onboarding-redesign`, NOT develop — the parity fixtures, Dart twin,
and `docs/ssot` mirror exist only there).

Contract: QA repo bundle tag `daily-macros-dashboard@v1` (mirrored verbatim at
`/docs/ssot`, pin in `docs/ssot/SSOT_SOURCE.txt`). Governance: vectors are the
contract; a red means wrong code or a needed ruling — never edit a vector to
pass (raise via the QA repo's `intake/` folder instead).

## What is implemented (as of 2026-08-17)

- **Engine v6.0.0** (`supabase/functions/calculate-daily-macros/`): ratified
  v5 pipeline — R1 unrounded chain, Q-003 strength flat 27 g/hr, Q-014 30 %E
  fat cap (step 10b, excess → carb), Q-009 `energy_basis` + no post-override
  recompute, manual-wins tomorrow, `delta: null` off the recalc path, BLOCK
  refuses. Retired: Garmin auto-promote, 1.5 g/kg fat ceiling, BLOCK fat-relax.
- **Conformance**: `vectors.conformance.test.ts` feeds all engine vectors from
  `docs/ssot/vectors/daily-macros/` — 167/168 green (the red is a defective
  vector, raised QA-side). Legacy engine suites migrated to the rulings.
- **Parity**: `DailyBaselineCalculator` (Dart mirror, onboarding preview)
  updated in lockstep; shared fixture regenerated by
  `calculate-daily-macros/tools/generate-parity-fixtures.ts` — never
  hand-edit it.
- **Schema**: Drift v18 — `activities.planned_time` / `actual_time` /
  `calories_burned` + `'deleted'` tombstone status; Supabase migrations
  `20260814120000` (two-time + tombstone) and `20260814121000`
  (`plan_recalc_log`).
- **F27 `recalculateAfterSync`** + one calibration row per run
  (`recalculate.ts`; retro mode in `index.ts` IS the F27 path).
- **Tombstones everywhere**: deleteActivity soft-deletes both sides; download
  paths include tombstones; change-detection + garmin-push/ping match
  tombstones FIRST (ruled key: platform id, else platform+sport+start ±15 min);
  disconnect purges deliberately stay hard-delete.
- **UI**: flag-gated `lib/features/macro_dashboard/` (fail-closed
  `MACRO_DASHBOARD_ENABLED`; Fuel Timeline remains default) — workout card
  (G1–G5/G7, Q-D1 verified suppression), energy card (3 faces × 2 expansions,
  P-1/P-2/Q-D3), timeline rail, Breakdown Pager (3 pages, live data), card tap
  → `openActivityFuel`. 10 goldens + 13 gesture tests per the design
  manifests + intraday-display vector suite (24) in
  `test/features/macro_dashboard/` and `test/features/daily_macros/`.

**Deploy-coupled constants — do not flip early:**
`_expectedAlgorithmVersion` in `daily_macro_targets_repository.dart` is held
at `'v5.0.0'` until the v6 engine deploys (flipping early causes a cache
invalidation storm — the 2026-08-14 dashboard flicker); Supabase
`app_config.current_schema_version` → 18 only when the build carrying Drift
v18 ships (triggers client delete-and-resync).

## Remaining plan

### Phase A — tests ✅ DONE (2026-08-17)
1. **Serialization round-trip test** ✅
   `test/features/activities/data/activity_two_time_roundtrip_test.dart`
   (9 tests): full chain domain → companion → real in-memory Drift row →
   upload payload → JSON wire → domain, plus every `ActivityMapper` seam
   individually; pins the three new columns, the tombstone + `deleted_at`,
   and the forInsert `planned_time` stamping on both insert seams.
2. **Screen-level widget test** ✅
   `test/features/macro_dashboard/macro_dashboard_screen_test.dart`
   (5 tests): the real screen + real `macroDashboardDay` provider/assembler
   with the six upstream sources overridden on the canonical mock day —
   filter lens, tracking-off §5, rail toggle, E1/P-1 expansion. Exact energy
   numbers stay pinned by the gestures suite (the screen path uses the wall
   clock).
3. **Patrol flow** ✅ `integration_test/flows/macro_dashboard_flow_test.dart`
   — PASSED on-simulator 2026-08-17. `macro_dashboard.*` ValueKeys added
   across the feature (filter pills, toggles, energy card/expand/breakdown,
   add pills, per-card keys, delete button, pager). The flow seeds its own
   workout via the real controller, then: G1 swipe → net-figure move +
   self-reported chip; two-time asserts against the app's live Drift DB
   in-process (actual_time set / planned_time untouched; G2 clears to null);
   S-4 expansion survival; pager walk; delete → local tombstone row
   persists. Remote-half assertions (Supabase row, `needs_upload` cleared)
   self-skip while `activities.planned_time` is un-migrated and arm
   automatically after Phase C.

   Fallout fixed along the way: `MacroDashboardScreen` discarded the
   futures of `markWorkoutDone`/`markWorkoutUndone`/`deleteActivity` — all
   three rethrow after rolling back, so a failed write became an uncaught
   zone error with no user feedback; the screen now awaits them guarded and
   surfaces failures via `MealvanaSnackbar`.

   **Patrol triage note**: the app bootstrap replaces `FlutterError.onError`
   (Sentry), so ANY failed `expect` in a flow dies as a generic
   "test overrode FlutterError.onError" assert and then wedges xcodebuild
   indefinitely. The flow chains a debugPrint tap in front of the app
   handler so the device log names the real failure — copy that pattern
   into new flows.
